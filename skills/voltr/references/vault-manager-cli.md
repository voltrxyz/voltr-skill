# Vault Manager — CLI (`sdk-scripts`)

> When to read this: operating a Voltr vault from the command line — the recommended default for admins and managers. Read [architecture.md](./architecture.md) first. To embed the builders in your own code instead, see [vault-manager-sdk.md](./vault-manager-sdk.md) and [../examples/sdk/](../examples/sdk/).

The `sdk-scripts` repo (`github.com/voltrxyz/sdk-scripts`) is one CLI exposing every vault and strategy operation as a `<group>:<action>` command. Operational values come from a JSON **profile**; per-call values are **flags**; secrets are never in the profile. Command names below are verified against `apps/cli/src/commands/`.

## Install

```bash
git clone https://github.com/voltrxyz/sdk-scripts.git
cd sdk-scripts
pnpm install
# validate the bundled example profile (fully offline — no RPC, no keypair):
pnpm cli -- --profile configs/examples/usdc.mainnet.example.json check
```

`pnpm cli -- <args>`: the leading `--` separates pnpm's args from the CLI's; the CLI strips it. Repo-relative `--profile` / `--*-keypair` paths resolve from where you run `pnpm cli` (the repo root).

## Profiles

One JSON file = one vault deployment. Validated with zod on load (a missing/malformed field fails before any RPC call). Copy `configs/examples/usdc.mainnet.example.json` to `configs/my-vault.json` and edit:

```jsonc
{
  "name": "my-vault",                       // required, non-empty; use neutral names
  "cluster": "mainnet-beta",                // localnet | devnet | mainnet-beta
  "rpcUrl": "",                             // optional fallback RPC (env/flag override it)
  "vault": {
    "name": "My USDC Vault",                // optional display label
    "assetMintAddress": "<ASSET_MINT>",     // required
    "assetTokenProgram": "<TOKEN_PROGRAM>", // required (Token or Token-2022)
    "vaultAddress": "<VAULT_ADDRESS>",      // generated by vault:init — leave empty until then
    "useLookupTable": false,
    "lookupTableAddress": "<LUT_ADDRESS>"   // required only when useLookupTable is true
  },
  "integrations": {
    "kamino":   { "reserveAddress": "<RESERVE>", "kvaultAddress": "<KVAULT>", "directWithdrawDiscriminator": [/* 8 bytes */] },
    "spot":     { "foreignMintAddress": "<MINT>", "foreignTokenProgram": "<PROG>", "assetOracleAddress": "<ORACLE>", "foreignOracleAddress": "<ORACLE>", "directWithdrawDiscriminator": [/* 8 bytes */] },
    "trustful": { "strategySeedString": "<SEED>" }
  }
}
```

Empty strings / empty arrays mean "not provided" — only fill what a command needs. `pnpm cli -- --profile configs/my-vault.json check` prints which fields/integrations are configured (offline).

## Keypairs & roles

Each command signs as one of four roles. The keypair path resolves from a **flag, falling back to an env var — the flag wins.** If neither is set, the command fails up front naming both.

| Role | Flag | Env var | Used by |
|---|---|---|---|
| `admin` | `--admin-keypair` | `ADMIN_KEYPAIR` | `vault:init*`, metadata, config, adaptor admin, harvest-fee, accept-admin |
| `protocol admin` | `--admin-keypair` | `ADMIN_KEYPAIR` | protocol treasury/admin changes and per-vault adaptor-policy overrides |
| `manager` | `--manager-keypair` | `MANAGER_KEYPAIR` | strategy operations (`kamino:*`, `spot:*`, `trustful:*`, claims) |
| `user` | `--user-keypair` | `USER_KEYPAIR` | deposit/withdraw, direct-withdraw |

```bash
# .env (gitignored) — copy .env.example and set once:
RPC_URL=https://your-rpc
ADMIN_KEYPAIR=/path/to/admin.json
MANAGER_KEYPAIR=/path/to/manager.json
USER_KEYPAIR=/path/to/user.json
```

Safe handling: no keypair material in profiles (only paths); prefer env over flags so paths don't land in shell history; keep keys outside the repo, `chmod 600`. The role keypair is resolved **before** dispatching the mode, so a valid keypair is required even for `--mode print` (it derives the signing authority; nothing is signed in print). The read-only `*:query:*` commands and `check` need **no** keypair.

## RPC precedence

First non-empty wins: `--rpc-url` flag → `RPC_URL` env → `HELIUS_RPC_URL` env → `profile.rpcUrl`. Every command **except `check`** builds an RPC-backed context up front — a URL must resolve even for `--mode print`. Keep authenticated (API-key) RPC URLs in env/`.env`, not committed profiles.

## Transaction modes — NEVER execute blind

Every transaction command takes `--mode` (default `print`). A command **builds first** (reading chain state over RPC, and the Jupiter API for swaps), then dispatches the mode. The build runs in *every* mode, so a reachable RPC is needed except for `check`.

| Mode | Sends? | Network after build | What it does with the built operation |
|---|---|---|---|
| `print` *(default)* | No | none | Prints `{ label, instructionCount, lookupTableAddresses }` + operation metadata. The no-send preview. |
| `simulate` | No | one `simulateTransaction` | Prints `OK`/`FAILED`, compute units, program logs, explorer URL. |
| `multisig` | No | none | Emits base64 + base58 transaction message (compute-budget stripped) to import into a multisig (e.g. Squads). Requires `--multisig-address`. |
| `execute` | **Yes** | send + confirm | Signs with the role keypair, sends, confirms; prints signature + compute units. |

**Recommended workflow — print → simulate → execute:**

```bash
pnpm cli -- --profile configs/my-vault.json --mode print    vault:deposit --amount 1000000
pnpm cli -- --profile configs/my-vault.json --mode simulate vault:deposit --amount 1000000
pnpm cli -- --profile configs/my-vault.json --mode execute  vault:deposit --amount 1000000
```

For a multisig-controlled admin/manager, swap execute for `--mode multisig --multisig-address <VAULT_SIGNER_PDA>` and import the printed payload. **`vault:init*` cannot use `--mode multisig`** (a fresh vault keypair must sign init, which a multisig payload can't carry) — use `--mode execute`.

### Global options (all transaction commands)

| Option | Purpose |
|---|---|
| `--profile <path>` | Profile JSON to load (required). |
| `--rpc-url <url>` | RPC override (see precedence). |
| `--mode <mode>` | `print` (default) / `simulate` / `multisig` / `execute`. |
| `--multisig-address <pubkey>` | On-chain signer PDA; required for `--mode multisig`. |
| `--priority-fee <kind>` | `helius` (default) / `rpc` / `fixed` / `none`. |
| `--priority-fee-micro-lamports <n>` | microLamports for `--priority-fee fixed` (or fallback). |
| `--compute-unit-limit <n>` | Override the estimated compute-unit limit. |

Discover exact per-command flags from the CLI itself: `pnpm cli -- <command> --help`.

## Command groups

| Group | Commands |
|---|---|
| **Vault core (admin/user)** | `vault:init`, `vault:init-and-set-token-metadata`, `vault:set-token-metadata`, `vault:update-config`, `vault:accept-admin`, `vault:harvest-fee`, `vault:deposit`, `vault:request-withdraw`, `vault:withdraw`, `vault:cancel-request-withdraw`, `vault:instant-withdraw`, `vault:query:position`, `vault:query:strategy-positions` |
| **Adaptor admin (admin)** | `vault:add-adaptor`, `vault:remove-adaptor`, `vault:init-direct-withdraw` |
| **Protocol admin** | `protocol:update-treasury`, `protocol:set-pending-admin`, `protocol:accept-admin`, `vault:update-adaptor-policy` |
| **Kamino (manager/user)** | `kamino:market:{init,deposit,withdraw,claim-reward,claim-reward-with-index}`, `kamino:kvault:{init,deposit,withdraw,claim-reward,claim-reward-with-index,direct-withdraw,request-and-direct-withdraw}` |
| **Spot (manager)** | `spot:swap:{init,buy,sell}`, `spot:earn:{init,extend-lut,deposit,withdraw,init-direct-withdraw}`, `spot:query:strategy-positions` |
| **Trustful (manager)** | `trustful:arbitrary:{init,deposit,withdraw}`, `trustful:curve:{init,borrow,repay,remove}` |
| **Maintenance** | `check` (offline profile validation) |

## Recipes

Assume `RPC_URL` + role keypairs are set in `.env`. Run each with `--mode print` then `--mode simulate` before `--mode execute`.

### Initialize a vault (admin)

```bash
# admin signs; manager is just an address. A fresh vault keypair is generated + printed.
pnpm cli -- --profile configs/my-vault.json --mode execute \
  vault:init --manager <MANAGER_PUBKEY> --name "My USDC Vault" --max-cap 100000000000

# Record the printed "Generated vault address" as vault.vaultAddress in the profile.

# (alt) init + LP-token metadata in one transaction:
pnpm cli -- --profile configs/my-vault.json --mode execute \
  vault:init-and-set-token-metadata --manager <MANAGER_PUBKEY> --name "My USDC Vault" \
  --max-cap 100000000000 --metadata-name "My USDC Vault Token" --metadata-symbol MYUSDC \
  --metadata-uri https://example.com/metadata.json
```

`vault:init` fee/duration flags default to `0`: `--start-at-ts`, `--manager-performance-fee`, `--admin-performance-fee`, `--manager-management-fee`, `--admin-management-fee`, `--locked-profit-degradation-duration`, `--redemption-fee`, `--issuance-fee`, `--withdrawal-waiting-period` (fees in bps; durations/caps in raw units). `--max-cap 0` = ZERO capacity; use the u64 max for uncapped.

### Config / metadata / fees (admin)

```bash
# Set/replace LP-token metadata later:
pnpm cli -- --profile configs/my-vault.json --mode execute \
  vault:set-token-metadata --metadata-name "My USDC Vault Token" --metadata-symbol MYUSDC \
  --metadata-uri https://example.com/metadata.json

# Update one config field per call (--field name + --value):
pnpm cli -- --profile configs/my-vault.json --mode execute \
  vault:update-config --field max-cap --value 200000000000
# field names: max-cap, start-at-ts, locked-profit-degradation-duration, withdrawal-waiting-period,
#   manager-performance-fee, admin-performance-fee, manager-management-fee, admin-management-fee,
#   redemption-fee, issuance-fee, manager, pending-admin, disabled-operations
# --value is a raw integer for numeric fields, a base58 address for manager/pending-admin.

# Transfer admin: set pending-admin, then the incoming admin accepts:
pnpm cli -- --profile configs/my-vault.json --mode execute vault:update-config --field pending-admin --value <NEW_ADMIN>
pnpm cli -- --profile configs/my-vault.json --mode execute vault:accept-admin   # signs with the incoming admin keypair

# Harvest accrued fees to manager/admin/protocol LP accounts:
pnpm cli -- --profile configs/my-vault.json --mode execute vault:harvest-fee --manager <MANAGER_PUBKEY>
```

### Add adaptors / register direct-withdraw (admin)

```bash
# Kamino (default adaptor):
pnpm cli -- --profile configs/my-vault.json --mode execute vault:add-adaptor
# Spot / Trustful / other — pass --adaptor-program:
pnpm cli -- --profile configs/my-vault.json --mode execute \
  vault:add-adaptor --adaptor-program EW35URAx3LiM13fFK3QxAXfGemHso9HWPixrv7YDY4AM   # Spot
pnpm cli -- --profile configs/my-vault.json --mode execute \
  vault:remove-adaptor --adaptor-program 3pnpK9nrs1R65eMV1wqCXkDkhSgN18xb1G5pgYPwoZjJ

# Register a direct-withdraw strategy (Kamino kvault default + profile discriminator):
pnpm cli -- --profile configs/my-vault.json --mode execute vault:init-direct-withdraw
# Overriding --adaptor-program requires --discriminator (8 comma-separated bytes).
# For Spot Earn, use the Spot command (derives strategy + program for you):
pnpm cli -- --profile configs/my-vault.json --mode execute spot:earn:init-direct-withdraw
```

### Deposit / withdraw (user)

```bash
pnpm cli -- --profile configs/my-vault.json --mode execute vault:deposit --amount 1000000

# Read-only position check (ignores --mode, no keypair):
pnpm cli -- --profile configs/my-vault.json vault:query:position --user <USER_PUBKEY>

# Standard withdraw: request, wait the lock period, claim:
pnpm cli -- --profile configs/my-vault.json --mode execute vault:request-withdraw --amount 1000000   # or --all / --in-lp
pnpm cli -- --profile configs/my-vault.json --mode execute vault:withdraw
pnpm cli -- --profile configs/my-vault.json --mode execute vault:cancel-request-withdraw

# Instant withdraw against idle assets (no waiting period):
pnpm cli -- --profile configs/my-vault.json --mode execute vault:instant-withdraw --amount 1000000   # or --all / --in-lp
```

`--in-lp` interprets `--amount` as LP tokens (else asset units); `--all` withdraws the entire position.

### Allocate funds — Kamino (manager)

Reserve/kvault come from `integrations.kamino.*`. The vault's per-strategy positions: `vault:query:strategy-positions`.

```bash
# Market reserve:
pnpm cli -- --profile configs/my-vault.json --mode execute kamino:market:init
pnpm cli -- --profile configs/my-vault.json --mode execute kamino:market:deposit  --amount 1000000
pnpm cli -- --profile configs/my-vault.json --mode execute kamino:market:withdraw --amount 1000000   # large amount = withdraw all

# kVault:
pnpm cli -- --profile configs/my-vault.json --mode execute kamino:kvault:init
pnpm cli -- --profile configs/my-vault.json --mode execute kamino:kvault:deposit  --amount 1000000
pnpm cli -- --profile configs/my-vault.json --mode execute kamino:kvault:withdraw --amount 1000000

# Claim one farm reward (omit --swap-amount when reward mint == asset mint):
pnpm cli -- --profile configs/my-vault.json --mode execute kamino:market:claim-reward \
  --reward-mint <REWARD_MINT> --farm-state <FARM_STATE> --user-state <USER_STATE> \
  --swap-amount <RAW_REWARD_AMOUNT> --slippage-bps 50
# multi-reward farms: kamino:{market,kvault}:claim-reward-with-index --reward-index 0 ...

# User direct-withdraw from the kvault strategy (requires vault:init-direct-withdraw first):
pnpm cli -- --profile configs/my-vault.json --mode execute kamino:kvault:direct-withdraw
pnpm cli -- --profile configs/my-vault.json --mode execute \
  kamino:kvault:request-and-direct-withdraw --amount 1000000   # or --all / --in-lp
```

### Allocate funds — Spot (manager)

Foreign mint/oracles from `integrations.spot.*`. Register the Spot adaptor first.

```bash
# Swap strategy: init, then buy (asset→foreign) / sell (foreign→asset):
pnpm cli -- --profile configs/my-vault.json --mode execute spot:swap:init
pnpm cli -- --profile configs/my-vault.json --mode execute spot:swap:buy  --amount 1000000 --slippage-bps 50
pnpm cli -- --profile configs/my-vault.json --mode execute spot:swap:sell --amount 1000000 --slippage-bps 50 --jupiter-max-accounts 16

# Jupiter Earn: init (then extend-lut if using a LUT), deposit, withdraw:
pnpm cli -- --profile configs/my-vault.json --mode execute spot:earn:init
pnpm cli -- --profile configs/my-vault.json --mode execute spot:earn:extend-lut
pnpm cli -- --profile configs/my-vault.json --mode execute spot:earn:deposit  --amount 1000000
pnpm cli -- --profile configs/my-vault.json --mode execute spot:earn:withdraw --amount 1000000

# Per-strategy positions with raw foreign-token balances (read-only):
pnpm cli -- --profile configs/my-vault.json spot:query:strategy-positions
```

`spot:swap:sell` performs a real foreign→asset Jupiter swap — simulate first.

### Allocate funds — Trustful (manager)

Arbitrary strategy named by `integrations.trustful.strategySeedString`; curve is a per-vault singleton (no seed flag). Register the Trustful adaptor first.

```bash
# Arbitrary (deposit prints the withdrawal-holding account — return assets there before withdrawing):
pnpm cli -- --profile configs/my-vault.json --mode execute trustful:arbitrary:init
pnpm cli -- --profile configs/my-vault.json --mode execute \
  trustful:arbitrary:deposit --amount 1000000 --destination <DESTINATION_TOKEN_ACCOUNT> --position-value-after 1000000
pnpm cli -- --profile configs/my-vault.json --mode execute \
  trustful:arbitrary:withdraw --amount 1000000 --position-value-after 0

# Curve: init, borrow, repay, remove:
pnpm cli -- --profile configs/my-vault.json --mode execute trustful:curve:init
pnpm cli -- --profile configs/my-vault.json --mode execute trustful:curve:borrow --amount 1000000 --borrow-rate-bps 50
pnpm cli -- --profile configs/my-vault.json --mode execute trustful:curve:repay  --amount 1000000 --borrow-rate-bps 50
pnpm cli -- --profile configs/my-vault.json --mode execute trustful:curve:remove
```

## Programmatic examples (`pnpm examples`)

For automation/bots/services embedding the builders directly, `examples/` holds one runnable TypeScript file per action (parallel to the CLI, not a second operator surface). They read the same profile + RPC precedence as the CLI; config comes from env (`VOLTR_PROFILE`, `RPC_URL`/`HELIUS_RPC_URL`, `<ROLE>_KEYPAIR`, `VOLTR_MODE`, `VOLTR_MULTISIG_ADDRESS`, `VOLTR_CONFIRM`), each overridable by a flag (`--profile`, `--rpc-url`, `--mode`, `--multisig-address`, `--yes`, `--help`).

```bash
export VOLTR_PROFILE=configs/my-vault.json
export RPC_URL=https://your-rpc
export MANAGER_KEYPAIR=/path/to/manager.json
pnpm examples:list                                 # catalog: group, role, network per example
pnpm exec tsx examples/src/kamino/market-withdraw.ts   # run a file directly
pnpm example -- kamino:market-withdraw             # …or by name via the dispatcher
pnpm examples:check                                # offline typecheck + runtime drift guard
```

Examples default to `print` and never send; `execute` is gated (type `yes`, or set `VOLTR_CONFIRM=1`). The `examples/src/composition/allocate.ts` file shows sequencing builders from more than one package through the shared processor. The skill's own runnable SDK examples (raw `@voltr/vault-sdk` + `@solana/kit`) are in [../examples/sdk/](../examples/sdk/).
